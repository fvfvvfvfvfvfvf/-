🏷️ Основные теги

  • <h1>...<h6> — заголовки (h1 — главный)
  • <p> — абзац
  • <a href="url">текст</a> — ссылка
  • <img src="путь" alt="описание"> — изображение
  • <ul><li>...</li></ul> — маркированный список
  • <ol><li>...</li></ol> — нумерованный список
  • <div> — блочный контейнер
  • <span> — строчный контейнер
  • <br> — перенос строки
  • <hr> — горизонтальная линия

📋 Семантические теги

  • <header> — шапка
  • <nav> — навигация
  • <main> — основное содержимое
  • <section> — смысловой раздел
  • <article> — самостоятельная статья
  • <aside> — боковая панель
  • <footer> — подвал

🔧 Git шпаргалка

⚙️ Первичная настройка

git config --global user.name "Ваше Имя"
git config --global user.email "email@example.com"
git config --global init.defaultBranch main

📦 Создание и клонирование

  • git init — инициализировать репозиторий в текущей папке
  • git clone <url> — склонировать удалённый репозиторий
  • git clone <url> <папка> — клонировать в указанную папку

📸 Базовый рабочий цикл

git status                  # состояние файлов
git add <файл>              # добавить конкретный файл
git add .                   # добавить все изменения
git commit -m "сообщение"   # зафиксировать изменения
git log --oneline           # история коммитов кратко
git diff                    # изменения до индексации

🌿 Ветки

  • git branch — список локальных веток
  • git branch <имя> — создать ветку
  • git checkout <ветка> — переключиться на ветку
  • git checkout -b <ветка> — создать и сразу переключиться
  • git switch <ветка> — современный аналог checkout
  • git merge <ветка> — слить ветку в текущую
  • git branch -d <ветка> — удалить ветку

🌐 Удалённые репозитории

git remote add origin <url>   # привязать удалённый репозиторий
git remote -v                  # список удалённых репозиториев
git push -u origin main        # первый пуш с привязкой
git push                       # отправить изменения
git pull                       # забрать изменения

⏪ Отмена и восстановление

git restore <файл>              # отменить изменения в файле
git restore --staged <файл>     # убрать из индекса
git reset --soft HEAD~1         # отменить коммит, сохранив изменения
git reset --hard HEAD~1         # удалить коммит и изменения
git revert <хэш>                # создать обратный коммит

📥 Временное сохранение (stash)

git stash          # спрятать изменения
git stash list     # список stash
git stash pop      # вернуть последние изменения
git stash drop     # удалить последний stash

🐙 GitHub шпаргалка

🚀 Публикация локального репозитория

git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/user/repo.git
git push -u origin main

🔀 Пул-реквест (PR)

# 1. Создать ветку под задачу
git checkout -b feature/new-button

# 2. Внести изменения и закоммитить
git add .
git commit -m "add new button"

# 3. Запушить ветку
git push -u origin feature/new-button

# 4. На GitHub: Compare & pull request → Create pull request

🔄 Синхронизация с форком

git remote add upstream https://github.com/original/repo.git
git fetch upstream
git checkout main
git merge upstream/main
git push origin main

⚡ GitHub Actions — базовый workflow

# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm test

🤖 Промты шпаргалка

🎯 Формула промта

Роль + Задача + Контекст + Формат + Ограничения

Роль:       "Ты — senior Python-разработчик"
Задача:     "Напиши функцию парсинга JSON"
Контекст:   "На входе список словарей с полями id, name"
Формат:     "Ответь кодом с комментариями"
Ограничения:"Только стандартная библиотека"

🧠 Техники

  • Zero-shot — прямой запрос без примеров
  • Few-shot — дать 2–3 примера перед задачей
  • Chain-of-thought — добавить «Решай пошагово»
  • Ролевой — «Представь, что ты…»
  • Self-consistency — «Дай 3 варианта ответа»
  • Рефлексия — «Проверь свой ответ и исправь ошибки»

💻 Промт для кода

Роль: Ты — опытный Go-разработчик.
Задача: Напиши HTTP-сервер с одним эндпоинтом /health.
Контекст: Go 1.22, без внешних библиотек.
Формат: Один файл main.go с комментариями.
Ограничения: Порт 8080, ответ JSON {"status":"ok"}.

✍️ Промт для текста

Роль: Ты — редактор деловой переписки.
Задача: Перепиши письмо в официально-деловом стиле.
Контекст: Письмо партнёру о переносе встречи.
Формат: 3–5 предложений, без воды.
Ограничения: Обращение на «Вы», без канцеляризмов.

📊 Промт для анализа

Роль: Ты — data-аналитик.
Задача: Найди аномалии в таблице продаж.
Контекст: CSV с колонками date, product, qty, price.
Формат: Список аномалий с пояснением.
Ограничения: Учитывай сезонность и выбросы > 3σ.

🔁 Уточняющие фразы

  • «Объясни проще, как для новичка»
  • «Приведи конкретный пример»
  • «Сократи до 5 пунктов»
  • «Покажи альтернативный подход»
  • «Разбей на шаги»
  • «Укажи источники или документацию»
